# Playground interface

Mode: Operate. Use the conventional Prettier-style playground layout for editing
code, checking formatting, and sharing reproductions.

Use a compact application header, a settings rail, and equally weighted input and
output editors. Preserve the original input when formatting so shared examples can
reproduce issues. Compare adds a native Prettier view to the output pane. Options
and JSONC are alternate views of one configuration. Plugin selection and examples
are discoverable without leaving the editor. On narrow screens the rail becomes
a collapsible panel and editors stack vertically.

Light surfaces support reading code in daylight; a dark theme follows the system
unless the user selects a preference. Use platform sans for controls and monospace
only for code. Quiet neutral dividers, a restrained teal action color, visible
focus rings and clear loading/error states keep attention on the code.

Do not introduce marketing sections, decorative cards, imagery or modal onboarding.
